Lighter model queries

A model is useful when the question is repetitive and the answer can be checked. It is the wrong tool when the cost of a wrong line is a place, a person, or a repair that cannot be undone from a screen.

I keep the heavy queries off by default. If a note can be sorted with a rule, I use the rule. If a draft needs a model, I prefer one that runs on the machine, so the text does not have to leave. When a larger model is the only thing that will do, I want a record of why that step ran: what was asked, what came back, and that I accepted it.

Agents help me draft and compare. They do not get the last word. Lighter, here, means fewer calls, smaller context, and a trail I can read later.
